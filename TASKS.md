Разрешённые файлы: `backend/models/session.py`, `backend/models/queue_entry.py`, `backend/routes/sessions.py`, `backend/db/migrations/*`, `tests/sessions/*`

### Детали реализации
- создать `Session` с `frozen=false` и без RSVP-полей;
- при `POST /sessions` в одной транзакции создать по одному `QueueEntry` на каждого уникального студента из групп и явного списка;
- отсортировать исходные записи по `full_name`, при совпадении — по `id`; назначить последовательные позиции;
- не создавать никакой автоматической отмены сессии: `cancelled` доступен только через действие преподавателя.

### Проверки: 0/4
- [ ] создание сессии сразу создаёт записи всех уникальных выбранных студентов в алфавитном порядке;
- [ ] повторное попадание студента через группу и явный список не создаёт дубликат;
- [ ] пустая активная очередь не меняет статус сессии на `cancelled`;
- [ ] в модели, API и тестах отсутствуют RSVP-поля и сценарии «нулевых подтверждений».
