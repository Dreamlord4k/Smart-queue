### Цель и разрешённый scope
Реализовать Redis Pub/Sub и защищённую WebSocket-подписку на `session:{id}`, публикацию всех согласованных изменений строго после commit, обновление обоих экранов без ручной перезагрузки и 5-секундный polling fallback с возвратом к WebSocket.

### Решение
- Полный WebSocket+Redis вариант, без сокращения до polling-only.
- Событие содержит идентификатор события, тип, session_id и время; состояние перечитывается через существующий GET, поэтому Redis не становится источником истины.
- Публикация выполняется только после успешного `db.commit()` и не откатывает уже сохранённую бизнес-операцию при недоступности Redis.
- WebSocket проверяет access JWT и доступ: преподаватель — только владелец сессии, студент — только участник.
- При потере WebSocket клиент включает один polling-таймер на 5 секунд, продолжает reconnect и выключает polling после восстановления, не запуская параллельные обновления.
