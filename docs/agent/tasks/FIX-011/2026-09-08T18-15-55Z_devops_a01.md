Исполнитель: devops
Начато: 2026-09-08T18-15-55Z

### Цель и разрешённый scope
Добавить два самостоятельных сценария автозапуска: POSIX `sh` для macOS/Linux и PowerShell 5.1+ для Windows. По умолчанию запускать local, по флагу — production HTTPS; безопасно обновлять код, проверять `.env`, секреты и порты, выполнять `down` без volumes, собирать стек, ждать `/health` не более 90 секунд, повторно применять миграции и выводить статусы/URL. Существующие `setup.sh`/`setup.ps1`, compose-файлы и код сервисов не менять.

Файлы: `scripts/local-up.sh`, `scripts/local-up.ps1`, этот отчёт. `TASKS.md` не изменяется.

### Команды и результаты
- `sh -n scripts/local-up.sh` — успешно.
- `dash -n scripts/local-up.sh` — успешно, bashisms не обнаружены синтаксическим разбором dash.
- `scripts/local-up.sh --help` — успешно.
- изолированный прогон без `.env` — exit 2, `.env` создан как неизменённая копия `.env.example`, Docker не вызван.
- повторный изолированный прогон с существующим placeholder `.env` — exit 1, файл побайтно сохранён, выведено действие для исправления.
- изолированный `--prod` с валидными dummy-секретами и placeholder DOMAIN — exit 1 до Docker с понятной ошибкой FQDN.
- PowerShell/pwsh в текущем macOS-окружении отсутствует; `.ps1` проверен статически на совместимый синтаксис и симметрию шагов, полноценный запуск требуется на Windows PowerShell 5.1+.
- реальный `down/up` намеренно не запускался при проверке, чтобы не прерывать пользовательский стенд и не выполнять `git pull` в рабочем репозитории.

### Блокеры / найденные риски
- задача дана как техническое дополнение вне актуальной сетки `TASKS.md`, поэтому используется следующий префикс `FIX-011` и `TASKS.md` не редактируется.
- PowerShell-проверка на Windows остаётся ручной из-за отсутствия интерпретатора в текущем окружении.

Создать один коммит в `fix/FIX-011` и открыть PR без merge; на Windows выполнить безопасный `-Help`, затем первый запуск с тестовым `.env`.
