### Решение
- Пользователь разрешил прямой доступ к PostgreSQL только для создания и очистки изолированных синтетических групп, потому что публичного API создания групп нет.
- Пользователи, две сессии и все бизнес-переходы создаются/выполняются через публичный HTTP API.
- Realtime-события в ручном прогоне читаются из Redis. Эти же события передаются существующему notification-сервису с памятью fake-транспорта; реальный Telegram API не вызывается.
- Демо использует фиксированный seed и namespace запуска, удаляет только собственные аккаунты через API и повторно создаёт предсказуемый набор.
