### Решение
- `POST /telegram/link/init` возвращает состояние привязки; для непривязанного студента выпускает криптографически случайный одноразовый код с TTL 10 минут, для уже привязанного — не создаёт лишний код.
- Один обработчик Telegram update используется webhook и long polling; Telegram не выдаёт токены входа.
- `NotificationLog` хранит стабильный ключ логического события и получателя, состояние доставки, число попыток и ошибку. Ошибка транспорта фиксируется после изменения очереди и допускает повторную доставку.
- `soft` рассчитывается фоновым проходом с порогом 900 секунд; `buffer` и `hard_call` запускаются подписчиком от событий очереди. Источник истины — PostgreSQL.
- Для локальной разработки бот работает через long polling; production webhook подключается к HTTPS на инфраструктурном этапе T-014.
