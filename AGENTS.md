# Общие правила

- Все документы, планы, статусы и handoff пишите на русском.
- Перед BUILD читайте: PRODUCT.md → PLAN.md → TASKS.md → файл текущей попытки.
- Только основной агент изменяет TASKS.md.
- Каждый исполнитель при старте создаёт новый файл:
  `docs/agent/tasks/<TASK-ID>/<UTC>_<OWNER>_aNN.md`
- Субагент возвращает путь к файлу и не переписывает чужие отчёты.
- Перед изменением `backend/` прочитайте `backend/AGENTS.md`.
- Перед изменением `tests/` прочитайте `tests/AGENTS.md`.
- Не загружайте все rules и skills заранее.
- Не создавайте новый PLAN.md, если существующий остаётся корректным.
- Прежде чем закрыть этап PLAN.md и перейти к следующему, перечисли ВСЕ пункты, которые этот этап называет явно, и убедись, что каждый закрыт хотя бы одной задачей в TASKS.md — статусом TODO или DONE. Если пункт не покрыт — сначала заведи под него задачу, и только потом переходи дальше.
- Не-фичевые технические правки (стабилизация, хотфиксы) используют префикс `FIX-` вместо `T-`, с той же схемой веток/отчётов.
- Не передавайте в чат-аналитик (ChatGPT Plus/Qwen/GigaChat) реальные пароли, JWT-секреты, `.env` или токены Telegram-бота.
- После того как задача из TASKS.md реализована и все её тесты из раздела «Проверки» прошли — используй GitHub-интеграцию, чтобы закоммитить изменения в отдельную ветку `task/<TASK-ID>` и открыть Pull Request с кратким описанием (что сделано, какие тесты прошли). **Не мёржи сам** — PR ждёт подтверждения человека.
- Если GitHub-интеграция недоступна или упала с ошибкой — не пытайся обойти это через прямые git-команды в обход плагина, сообщи об этом в файле попытки как блокер.

## Неснимаемые бизнес-правила проекта (не менять без явного изменения PRODUCT.md)

- Студент может двигать в очереди **только свою собственную** запись — никогда чужую, проверка обязательна на бэкенде, а не только в UI.
- Нельзя вставить запись на позицию, уже занятую записью с `locked=true`.
- После `locked=true` запись не двигает даже её владелец, пока сам не снимет флаг.
- `lock_reason` — свободный текст; не превращать в структурированное поле, не классифицировать, не делать обязательным.
- Запрещено добавлять поля: здоровье, доход, национальность, биометрия, точная геолокация — в любом виде, даже опционально.
- Telegram — только канал уведомлений (линковка к существующему аккаунту), никогда не единственный способ входа/аутентификации.
